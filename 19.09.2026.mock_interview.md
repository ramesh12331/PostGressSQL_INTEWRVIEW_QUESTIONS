# 📚 SQL Concepts — Quick Summary

Here is a **beginner-friendly revision sheet** of everything we discussed.

---

## 1️⃣ What is SQL?

**SQL = Structured Query Language**

Used to interact with **relational databases**.

```sql
SELECT *
FROM Employee;
```

### SQL can:

* Create data → `INSERT`
* Read data → `SELECT`
* Update data → `UPDATE`
* Delete data → `DELETE`
* Create tables → `CREATE`
* Filter data → `WHERE`
* Group data → `GROUP BY`
* Join tables → `JOIN`

🧠 **Remember:**

> SQL = Language used to communicate with a relational database.

---

# 2️⃣ Primary Key 🔑

A **Primary Key** uniquely identifies every row in a table.

```sql
CREATE TABLE Employee (
    employee_id INT PRIMARY KEY,
    name VARCHAR(50)
);
```

### Rules

* ✅ Unique
* ❌ Cannot be `NULL`
* One primary-key constraint per table
* Identifies each record

Example:

```text
101 → Ramesh
102 → Ganesh
103 → Suresh
```

🧠 **Remember:**

> Primary Key = **Identity of a row**

---

# 3️⃣ Foreign Key 🔗

A **Foreign Key** creates a relationship between two tables.

```sql
FOREIGN KEY (employee_id)
REFERENCES Employee(employee_id);
```

Example:

```text
Employee
employee_id
     ↓
   101
     ↓
Orders
employee_id
```

### Rules

* References a key in another table
* Can have duplicate values
* Can be `NULL` unless restricted
* A table can have multiple foreign keys

🧠 **Remember:**

> Foreign Key = **Connection between tables**

---

# 4️⃣ UNIQUE 🔐

`UNIQUE` prevents duplicate values.

```sql
CREATE TABLE Employee (
    id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE
);
```

This is allowed:

```text
ramesh@gmail.com
ganesh@gmail.com
```

This is not:

```text
ramesh@gmail.com
ramesh@gmail.com ❌
```

### UNIQUE vs PRIMARY KEY

|                      | Primary Key  | UNIQUE             |
| -------------------- | ------------ | ------------------ |
| Duplicate            | ❌            | ❌                  |
| NULL                 | ❌            | Usually allowed    |
| Multiple constraints | One          | Multiple           |
| Purpose              | Identify row | Prevent duplicates |

🧠 **Remember:**

> UNIQUE = **Don't repeat this value**

---

# 5️⃣ UNION 🔄

`UNION` combines the results of two `SELECT` queries and **removes duplicate rows**.

```sql
SELECT name FROM Employee1
UNION
SELECT name FROM Employee2;
```

Example:

```text
Employee1 → Ramesh, Ganesh
Employee2 → Ganesh, Suresh
```

Result:

```text
Ramesh
Ganesh
Suresh
```

`Ganesh` appears only once.

🧠 **Remember:**

> UNION = **Combine + Remove duplicates**

---

# 6️⃣ UNION ALL 🔄

`UNION ALL` combines results and **keeps duplicates**.

```sql
SELECT name FROM Employee1
UNION ALL
SELECT name FROM Employee2;
```

Result:

```text
Ramesh
Ganesh
Ganesh
Suresh
```

🧠 **Remember:**

> UNION → duplicates removed
> UNION ALL → **All rows**

### ⚡ Performance

`UNION ALL` is generally faster because it doesn't need to remove duplicates.

---

# 7️⃣ COUNT() 🔢

`COUNT()` counts rows/values depending on how it is used.

### `COUNT(column)`

```sql
SELECT COUNT(salary)
FROM Employee;
```

`COUNT(salary)` **does not count NULL values**.

Example:

| salary |
| -----: |
|   NULL |
|  20000 |
|   NULL |
|  30000 |

Result:

```text
2
```

### `COUNT(*)`

```sql
SELECT COUNT(*)
FROM Employee;
```

Counts **all rows**, including rows where some columns contain `NULL`.

🧠 **Remember:**

```text
COUNT(column) → ignores NULL
COUNT(*)      → counts rows
```

---

# 8️⃣ ACID Properties 🏦

ACID properties make database transactions reliable.

### A → Atomicity

**All or nothing**

```text
Transaction succeeds completely → COMMIT
Transaction fails → ROLLBACK
```

🧠 Atomicity = **All or Nothing**

---

### C → Consistency

Database must remain in a **valid state** according to its rules and constraints.

🧠 Consistency = **Valid Data**

---

### I → Isolation

Concurrent transactions should be controlled so they don't improperly interfere with each other.

🧠 Isolation = **Transactions are isolated**

---

### D → Durability

After `COMMIT`, changes should remain saved even if a failure occurs afterward.

🧠 Durability = **Committed data stays**
